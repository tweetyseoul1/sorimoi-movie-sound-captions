# 실행과 비교 방법

이번 실행은 이미 설치된 OnSori Python 환경과 로컬 AST 가중치를 사용했습니다. 모델 가중치는 저장소에 포함하지 않았으며, 인터넷에서 자동으로 내려받지 않습니다. 정확한 라이브러리 버전은 `runtime-versions.json`에 보존했습니다.

모델: `MIT/ast-finetuned-audioset-10-10-0.4593`, revision `f826b80d28226b62986cc218e5cec390b1096902`.

## 재현

1. 같은 모델 가중치가 있는 OnSori Python 환경에서 저장소 루트를 작업 폴더로 사용합니다. `analyze.py`는 환경 상위 폴더 또는 `%LOCALAPPDATA%/OnSori`의 기존 모델을 찾습니다.
2. `python evaluation/analyze.py assets/movie-clip.mp4 --out local-results`를 실행합니다.
3. `python evaluation/compare.py local-results/result.json`을 실행합니다. 이 단계는 Python 표준 라이브러리만 사용하며 비교 페이지와 표를 다시 생성합니다.

## 고정한 조건

- 원본 00:30~01:30에서 발췌한 동일 파일. 비교 단계에서 입력 SHA-256과 배포 영상의 SHA-256이 같은지 검사합니다.
- 16kHz 모노, 2초 분석 창, 1초 이동. 최상위 분류 하나가 sigmoid 출력 0.24 이상일 때 후보로 사용합니다. 음악도 후보로 보존합니다. 말소리·대화·해설·무음 분류는 효과음 후보에서 제외합니다.
- 참고 자막은 추론 입력에 사용하지 않았습니다. 전체 실행이 끝난 후 `comparison-rules.json`으로 비교했습니다. 규칙은 완료된 결과를 보기 전에 작성했으며, 결과를 보고 모델 기준을 조정하지 않았습니다.
- 같은 소리 종류와 0.1초 이상 겹치면 해당 참고 구간에 동종 후보가 있다고 기록합니다. 이는 정확한 소리 원인이나 세밀한 시각이 맞았다는 뜻이 아닙니다.
- 시작·끝 시각이 모두 참고 자막의 ±1초 안인지 별도로 기록합니다. 같은 병합 후보가 여러 참고 구간을 덮을 수 있으므로 독립 검출 개수나 정식 재현율로 해석하지 않습니다.
- 상위 5개 분류는 원자료에 보존했지만, 최종 출력이 아닌 차순위 후보를 사후에 맞힌 것으로 올리지 않았습니다.
- 다른 분류나 참고 자막에 없는 후보는 독립 청취 검수 없이 오탐이라고 확정하지 않습니다. 참고 자막도 불완전하므로 정밀도·재현율을 산출하지 않았습니다.

## 결과

이번 실제 실행은 음악 5개 구간만 출력했습니다. 참고 자막의 11개 구간에서 동종 효과음 후보를 찾은 구간은 0개입니다. 10개는 효과음 후보 없음, 하품 1개는 독립 분류 항목 없음으로 기록했습니다. 현재의 최상위 분류 하나만 사용하는 방식은 배경음악과 겹친 효과음을 놓칠 수 있습니다.

다음 시험에서는 같은 자료를 유지하면서 동시에 여러 소리를 출력하는 설정이나 다른 소리 감지 모델을 별도 조건으로 비교하고, 사람이 청취한 정답표를 마련해야 합니다. 이번 결과를 그 개선 시험의 결과로 대체하거나 부풀리지 않습니다.
